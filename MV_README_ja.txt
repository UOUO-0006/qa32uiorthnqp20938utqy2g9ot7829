DDBBS MV · Build07 インストールと使い方

Build ID: DDBBS-MV-20261019-07
このZIPは既存サイトへの追加差分です。通常版 DDBBS.html、Build05、Build06 は含まず、変更しません。
公開サイトへのデプロイも行いません。

■ インストール
1. ZIP内の html/DDBBS_MV.html を、サイトの html フォルダーへコピーします。
2. ZIP内の image/mv_runtime.js を、サイトの image フォルダーへコピーします。
3. ZIP内の capture_helper.py、start_capture_helper.bat、requirements.txt は、PC上の任意のフォルダーへ保存します。
4. 既存サイトで使っている画像素材（image/）はそのまま使います。通常版 html/DDBBS.html は変更・上書きしません。MVページの元インラインスクリプトは元ファイルと完全一致（`a=30` の行削除を含む）です。無限スクロール補助はMV専用 `mv_runtime.js` のみで行い、撮影中だけ見えない高さ保持スペーサーと末尾の小さなトリガー余白を使います。停止時にスペーサーをリセットします。

■ 初回準備（Windows / Chrome）
1. Python 3.10 以降と Google Chrome をインストールします。
2. 補助処理のフォルダーでコマンドプロンプトを開き、次を一度実行します。
   py -3 -m pip install -r requirements.txt
3. start_capture_helper.bat を起動します。コマンド画面に、Build07ページのHTTPS URLか、html と image を含むサイトフォルダーのパスを入力します。
   ローカルサイトフォルダーを指定すると、この補助処理が一時HTTPサーバーを起動します。
4. PlaywrightがChromeを起動します。ページが読み込まれたら、ページ内で開始位置までスクロールして「録画開始」を押します。

■ 録画仕様
・無限スクロール継続（MV runtimeのみ）: ページ本文の `a=30` と旧行削除処理は元のままです。撮影中だけruntimeが削除行の高さを見えない先頭スペーサーとして保持し、scrollHeightが縮むのを防ぎます。stickyヘッダー下でsentinelがroot外に残る小さな隙間は末尾の一時スペーサーで埋め、元のIntersectionObserverが元の `b()` を呼ぶ状態にします。行追加時に末尾スペーサーをリセットし、停止時は全スペーサーを解除します。HTML本文スクリプト、GIF確率、リンク生成、フィード生成・更新は変更しません。
・非同期Playwright＋asyncio.QueueでChrome DevTools ProtocolのPage.startScreencastをPNG形式で受信し、Chromeコンポジターの表示画素から4:3範囲 #c60 を切り出します。getDisplayMediaや動画コーデックは使いません。
・既存スクロール位置を保ち、1ステップ進んだ描画状態を frame_000000.png とします。以後、Chromeから受信したPNGを順番に保存し、後段でフレームを間引いたり複製したりしません。
・書き出しは1440×1080、連番PNG、読み込み30fps固定です。標準ブラウザー表示領域は1334×800、DPR 1です。起動時にrequestAnimationFrameの更新周期を計測し、60Hz表示ならCDPのPNG採取を2更新ごとにして30fpsを目指します。PNG処理が追いつかない場合は実測速度が下がります。ページタイマーやGIF時刻は操作しません。
・ブラウザーのCSS画素スクリーンショットをPNG化します。ピクセル丸めで4:3からずれた場合のみ中央を画素単位で切り出し、1440×1080へ最近傍法で合わせます。後段のアンチエイリアス、平滑化、閾値化、減色、ディザリング、非可逆圧縮はしません。
・Chromeのブラウザー描画自体が行うラスタライズはそのまま記録します。PNGはzlib圧縮レベル3の可逆圧縮です。
・停止ボタンまたはEscで停止します。保存先は初期設定でユーザーの Downloads フォルダーです。ZIPには連番PNGと日本語READMEを収録します。
・ZIPアーカイブ（PNGとZIP管理情報を含む）全体を500,000,000 byte以下に制限します。上限前に追加できる最後の完全なフレームまでを保存します。4,500枚を目安とし、圧縮のための減色やフレーム削減は行いません。
・PNGの個別タイムスタンプは追加しません。連番を30fpsで読み込みます。実測速度は最初の受信PNGから撮影終了までで計測し、ZIP READMEに記録します。

■ 検証状態（ローカル試験）
・添付された元Build07実録ZIPの監査: 52 PNG＋README（53 entries）、ZIP 4,659,380 byte。PNG合計4,652,181 byte、平均89,465 byte、p95 116,687 byte、最大117,635 byte、出力1440×1080、撮影元ステージ1016×762、実測22.13枚/秒。READMEのscrollTopは11458→11478→11312で、末尾停止の再現証拠です。ZIP整合性は成功。
・改訂runtimeで撮影helperからCDP PNGを取得し、行追加／削除が起きる末尾近くの位置から録画・ZIP保存を確認しました。viewport 1334×830のヘッドレスChromium試験は45枚、ZIP 3,155,204 byte、実測20.29枚/秒（30fps目標未達）。PNGは合計3,148,763 byte、平均69,973 byte、p95 76,851 byte、最大77,205 byte。試験時のみ乱数プロファイルを固定し、事前maxScrollTop=12167の実録条件を再現しています（製品側の乱数設定は変更なし）。
・平均換算は、今回の45枚試験からZIP約315,378,706 byte、添付52枚実録の平均からZIP約403,094,993 byte（それぞれ4,500 PNG＋管理情報／README予約の概算）。後者は500MB上限まで約96,905,007 byteの概算余裕ですが、いずれもサンプル推定であり、全4,500枚を撮影していないため容量保証ではありません。
・frame_000000.pngは1440×1080、可逆PNGです。同じCDP PNGフレームをcrop＋最近傍法で正規化した期待画像と一致することを確認しています。image-1.pngとの全画素一致は、別時刻の動的画面・表示環境の違いがあるため未確認です。
・無限スクロールの長時間stress: viewport1334×830・開始scrollTop11458で、PNGを保存しないruntimeステップだけを4,500回実行（約150秒、試験ハーネスの乱数プロファイル固定）。終了scrollTop101478/max101607、DOM30行、撮影中に160行追加・160行削除、ページエラーなし、停止後スペーサー0px。これはスクロール試験であり、4,500 PNG撮影試験ではありません。
・ZIP上限停止は2,000,000 byteの試験上限で模擬し、26枚、ZIP 1,960,021 byteで停止・整合性を確認しました。4,500枚の実撮影と実際の500,000,000 byte上限到達試験は未実施です。
・Build07は通常版・Build05・Build06から分離した候補です。公開デプロイはありません。
